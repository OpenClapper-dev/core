# @openclapper/design

The design system of the rewrite (epic #326, design track D3 #340): tokens, fonts, icons, marks and Preact components for the Studio, the admin board and the home site, plus the token object for the phone. It replaces `@openclapper/ui` in the rebuild; until then the current apps keep using `@openclapper/ui`, and the two must not be loaded on the same page (they share token names such as `--surface` and `--text` with different values).

Source: the designer's export "Graphite" (round 2, 2026-11-13), made from the brief in `docs/rewrite/design-brief.md`. The JSX reference components were ported to Preact + TypeScript one to one; class names, markup and CSS are unchanged.

## Use

- Web: `import "@openclapper/design/styles.css";` once, then components from `@openclapper/design`. Theme: `data-theme="light"` or `"dark"` on `<html>`; no attribute follows the OS. Names are exactly Light and Dark.
- Phone: `import { TOKENS } from "@openclapper/design/tokens";` (`TOKENS.light`, `TOKENS.dark`, `FIXED` over the camera and photos, `ENV`, `FONT`, `SPACE`, `SIZE`, `RADIUS`, `MOTION`, …). Under reduced motion (`AccessibilityInfo.isReduceMotionEnabled()`) use 0 for every `MOTION.dur*`. Icons: `tabler(name)` from `@openclapper/design/glyphs` gives the Tabler name for `@tabler/icons-react-native` (not added yet; custom film glyphs return null). The React Native components are not written yet; `src/phone/` holds web references with the props they should share.
- Specimens: `make specimen` (http://localhost:5175) shows every foundation card and component group in Light and Dark, and the assembled desktop, window templates and phone kits.

## Porting notes

- Hit areas cover the whole control: clicking anywhere in an input, select or combobox focuses or opens it.
- `AppWindow` owns its motion (open, `closing` → `onClosed`, FLIP on maximise/restore/snap, minimise toward `minimizeTarget`); the shell owns position and dragging, which never animate.
- Text inputs listen to `input`, not `change` (Preact's `onChange` is the DOM event, which fires on commit); the public callbacks keep the names of the export.

## Content fundamentals
- Sentence case everywhere, including buttons and titles: `Import photos`, not `Import Photos`.
- Units are spaced: `24 mm`, `±5 m`, `30 %`. A middle dot separates facts: `24 items · 2 selected · 48.2 MB`.
- No emoji. No exclamation marks. No "please".
- Short and literal. Buttons are verbs (`Import`, `Delete`, `Save`); states are single words (`Approved`, `Unreviewed`, `Failed`).
- Address the user as "you" only when needed; the product never says "I" or "we".
- Numbers are for reading at a glance: mono, tabular, with the unit.
- Theme names are exactly **Light** and **Dark** (plus Auto, which follows the OS).

## Visual foundations
Values below are copied from `tokens/tokens.json` (proportions follow shadcn's default Vega style, tightened to its dense variant; the pre-nudge values are saved in `checkpoints/graphite-v1/`).

- **Character**: a quiet desktop in true greys. Cobalt is the only colour the chrome owns. Hierarchy comes from type and spacing, not boxes in boxes.
- **Themes**: Light and Dark, both high contrast. `data-theme="light|dark"` on `<html>`; with no attribute the OS setting decides.
- **Contrast**: body and labels ≥ 7:1, secondary text ≥ 4.5:1, control boundaries and focus ≥ 3:1. Two edges are decorative and carry no minimum: `--border-divider` and the unfocused window edge `--border-window` (see GUIDELINES → Contrast). The contrast card computes every pair live.
- **Colour**: greys with a trace of warmth (`--grey-0` … `--grey-950`); cobalt accent (`#0B45D9` Light, `#82A4FF` Dark); amber only for warnings; red for danger; green for success. State tints are backgrounds only; text on them stays `--text`. Eight categorical colours `--cat-1` … `--cat-8` and five chart colours `--chart-1` … `--chart-5`.
- **Never colour alone**: a state is colour plus an icon or label; selected is fill plus bold plus a check, bar or outline; disabled is a dashed edge and `--text-disabled`, never opacity.
- **Content never takes the theme**: photos sit on black (`--photo-bg`); frame lines, masks and labels over a photo or map use the fixed `--over-*` colours; nothing translucent carries text over a photo.
- **Type**: Atkinson Hyperlegible Next for UI, Atkinson Hyperlegible Mono for readouts. Kept because it was drawn for low vision: 1 l I and 0 O differ by design, which is what glare needs. Web scale 12 / 13 / 14 / 16 / 18 / 24 / 30 px (`--font-size-2xs` … `-3xl`); body and control labels 14 px, secondary 13 px, micro 12 px. Phone 14 / 16 / 20 / 24. Leading 1.15 (tight), 1.3 (UI), 1.45 (body). Weights 400, 500, 600, 700: buttons and field labels 600, section heads and selected items 700.
- **Numbers**: the sans with tabular figures (`.oc-tnum`) in property lists, table columns and status bars; Mono (`.oc-num`) for timecode, the clock, camera readouts, ticking values, keys, codes and meta lines. See the "Numbers: mono vs tabular sans" card.
- **Density**: compact. Controls 28 px (`--control-h`; 24 small, 36 large, 48 dp touch), rows 28 px (`--row-h`; 32 for section heads), title bar 32 px, toolbar 40 px, taskbar 40 px, status bar 24 px. Icons 12 / 16 / 20 px. Spacing 2 / 4 / 6 / 8 / 12 / 16 / 24 / 32 / 48 px (`--space-1` … `-9`). Buttons and inputs have 10 px side padding.
- **Shape**: 6 px for controls, menus and chips (`--radius-control`); 4 px for badges, keys and checkboxes (`--radius-xs`, `--radius-sm`); 10 px for cards, dialogs and windows (`--radius-card`, `--radius-window`); pill for switches, slider knobs, count badges and avatars. Choice chips fill with the accent when chosen; segmented controls and tabs are a muted track with a raised selection.
- **Borders**: 1 px (`--border-w`) everywhere; 2 px (`--border-w-strong`) for invalid fields and drop targets.
- **Focus**: a 1 px `--focus` ring plus a 4 px `--focus-ring` halo, drawn as a box-shadow. Over photos and in the camera, where a halo would sit on content, a 2 px outline (`--focus-w`) in `--over-human`, set off the control. Focus never animates.
- **Hover** is one step of grey (`--surface-hover`); **pressed** one more (`--surface-pressed`). No shrink, no shadow change. Primary steps through `--accent-hover` and `--accent-pressed`.
- **Elevation**: `--shadow-xs` under controls, `--shadow-card` under cards, `--shadow-window` / `--shadow-window-focused` for windows, `--shadow-menu`, `--shadow-toast`. A focused window is also marked by a darker edge (`--border-window-focused`, ≥ 3:1), a tinted title bar and a bold title.
- **Backgrounds**: flat. No gradients, textures or illustrations in chrome. The desktop is a plain grey (`--bg-desktop`).
- **Transparency and blur**: none in chrome. `--scrim`, `--marquee` and `--focus-ring` are the only translucent tokens.
- **Cards**: `--surface`, a 1 px `--border-divider` edge, 10 px radius, `--shadow-card`, 16 px padding. Never nested.
- **Motion**: 90 ms (hover, colour, close), 160 ms (menus, toasts, tabs, collapse, window open), 240 ms (dialogs, maximise, snap, task view, sheets). `--ease` to enter, `--ease-in` to exit. Menus enter but close instantly. Never moves: focus rings, text, photos, frames, anything following a pointer. Reduced motion zeroes the duration tokens; spinners keep turning.
- **Environments**: production `#1E3FBF`, staging `#B8471F`, development `#3B7A1A` (`--env-*`), as icon ground and as an in-app marker with a label.

## Iconography
- **One set: Tabler Icons** (v3.51.0, outline, MIT; tabler.io/icons), decided by the owner on 2026-11-13 for UI glyphs, app icons and file-type icons alike. No second set, no filled variants.
- `components/core/glyphs.js` bundles the icons under OpenClapper aliases (`close` → `x`, `image` → `photo`, `warning` → `alert-triangle`, `lens` → `aperture`, `shortcut` → `arrow-up-right`). The `Icon` component renders them; `assets/icons/<alias>.svg` holds the same icons as files, with the tabler name in a comment. Licence: `assets/icons/LICENSE-tabler.txt`.
- **Film glyphs**: eight concepts Tabler does not cover are drawn in-house to Tabler rules and live in `assets/icons/film/` and glyphs.js (source `custom`): framing, sensor-size, focal-reducer, light-fixture, camera-layout, slate, zebra, anamorphic. Others map to Tabler (thirds → `grid-3x3`, aspect → `aspect-ratio`, histogram → `chart-histogram`, focus-assist → `focus-centered`, color-temp → `temperature-sun`, practical → `bulb`). See the "Film glyphs" card.
- Rules: 24 grid, 2 px stroke, round caps and joins, outline, `currentColor`. Stroke follows size (2.5 at 12 px, 2 at 16 px, 1.75 at 20 px) so lines stay about 1.5 px on screen.
- **App and file-type icons**: `AppIcon` puts a Tabler glyph on a categorical tile (`--cat-*`, 22 % radius). An extension that is off gets a dashed tile.
- Adding an icon: find it on tabler.io/icons, copy the outline markup into glyphs.js under a short semantic name, save the SVG in assets/icons. Draw a custom glyph only when no Tabler icon carries the meaning, and follow the rules above.
- No emoji, no unicode characters as icons, no icon font.

## Marks
- **Mark**: the slate corner, refined. A clapper board whose body runs off the bottom-right edge, a hinge hole, a four-block stick rising at 18°. Built on a 64-unit tile by `assets/marks/build-marks.js` (single source; regenerate rather than edit files).
- **Environments**: colour only on the mark (production ultramarine `#1E3FBF`, staging clay `#B8471F`, development moss `#3B7A1A`), same solid board for all; the hatched and outlined variants were dropped because they did not read at small sizes. In the UI, `EnvMarker` adds the label, so the environment is never colour alone there.
- **Clients**: a Tabler glyph cut from the board: Studio `app-window`, phone `device-mobile`, admin `lock`. The home site and the organisation avatar use the plain mark. Below 48 px the glyph is dropped (`*-small.svg`).
- **Files**: `assets/logo.svg`; `assets/marks/<client>-<env>.svg` and `-small.svg`; `wordmark(-inverse).svg`, `lockup(-inverse).svg`; `android/phone-<env>-{foreground,background,monochrome}.svg`; `png/` holds favicons 16/32, web icons 192/512 and maskable 512 for Studio, admin and home, Android adaptive layers at 432 px, phone icon 512, org avatars 512, and `social-preview-1200x630.png`.
- Wordmark: Atkinson Hyperlegible Next Bold, −1 % tracking, kerned. `wordmark(-inverse).svg` and `lockup(-inverse).svg` are outlined (no live text, no font dependency); `build-marks.js` still emits live text for previews, so re-outline after regenerating.
